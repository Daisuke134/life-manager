# Provider final-answer readback — corrective design (2026-10-23)

The official pinned OpenAI3.24.0 wheel exists and matches its PyPI hash `b59703a3e3b5df78b269e90049d383a1dda58c90104cc4be59db21078db4b7a4`. Static source confirms the currently used methods/signatures. This is a new corrective unit based on primary SDK evidence after PR8660, not another review round of the closed PR8650/8660.

Root causes: a followup output_text.done event is one content part, but the adapter overwrites the previous part and does not independently bind final text to saved items. Saved-item reads currently mix assistant commentary/incomplete messages into supported text. Initial collection has a turn ID but is joined to a latest saved turn without checking equality. Cancellation's pre-send vocabulary uses the Session state requires_action rather than Turn queued/in_progress/waiting.

Chosen fix: reuse the existing exact-turn saved-item reader and official SDK result semantics, with no new endpoint/client/recovery engine. Concatenate completed non-commentary saved assistant output_text blocks in ascending returned item order, without separators (same text convention as AgentTurnResult.output_text). The followup SSE completion identifies the target, not its authoritative text. Require the latest completed turn to match before and after item readback, then release the same application writer. Complete empty saved items mean silence only with existing explicit opt-in. Missing, malformed, nonterminal or incomplete readback remains SessionFailure, retaining writer/budget and preventing automatic resend.

Initial collection must carry its exact result.turn_id and match the saved latest completed turn before returning its text. read_completed_turn remains metadata-only when the SDK Turn has no output_text; that absence alone is not classified SILENT_COMPLETED. The helper's signature is unchanged.

Saved items: only the exact turn and assistant message type can contribute. Exclude phase commentary. Nullable phase None is accepted for a completed assistant message, matching the pinned SDK collector. Unknown phase, missing/non-completed status, malformed content or unsupported assistant text kind fails closed. Each accepted output_text block must be a string; enforce the existing16000char total while scanning. Preserve bounded pagination, explicit has_more bool, duplicate/cursor guards; do not infer completeness from SDK optional has_more=None.

Cancel: only canonical queued/in_progress/waiting nonterminal Turn states may request cancellation. requires_action is a Session state and remains UNKNOWN as an unsupported Turn state. Session-active cancel still has no turn_id/CAS argument. Preserve before/after exactID+status checks, HTTP202 uncertainty, bool/null cancellation_sent, checkpoint ACK-before-POST, writer fence, idempotency reservation, cap exposure and absolute deadline.

No public actions, live model/cancel calls, new dependencies, SDK installation, secret reads, schema changes, scheduled inference, owner/cadence/permission changes or registry acceptance. Tests use SDK-shaped fixtures and real journal/checkpoint; they do not establish live provider behavior. Official sources: https://pypi.org/pypi/openai/3.24.0/json and retained wheel `openai/types/beta/{agent_session_message,agent_session_turn_output_text_done_event,agent_session_input_param}.py`, `openai/types/beta/agents/sessions/turn.py`, `openai/lib/beta/agents/_result.py`; guide https://ampersand.humansand.ai/docs/GUIDES.html (retained2026-10-23T04:28:33Z).

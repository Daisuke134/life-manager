# Managerの最初の実証と効果測定

実行順・状態の正本は[統合SSOT](2026-09-25-life-manager-unified-ssot.md#manager-first-blessing-20261012)のみ。これは対象選択と実証設計の提案で、実装・運用・効果を完了した記録ではない。

## 第一候補

仕事紹介・受発注ネットワークで、仕事へのアクセス条件と案件配分を変更し、同じ外部予算で実現純所得と有給仕事への到達を改善する。受益者にManager account・個人credential・新しいchat interfaceを求めない。運営者の既存データと変更権限を使う。

一般的な価格最適化や広告売上だけを最終成果にしない。供給・参加・配分・時間条件という共有構造が、誰の機会と所得を変えたかを測る。本人の生活への効果を測る点でLife Managerの自社売上と区別する。

## 比較する三案

|案|変更する共有構造|生活上の測定|今月の制約|
|---|---|---|---|
|仕事・収入機会アクセス|既存要件のうち必須でない障壁、案件分割、時間条件、公開範囲、配分|実現純所得、完了、時間、分配、品質|実在需要、運営権限、参加可能集団、支払データが必要|
|サービス/医療アクセス|営業時間、予約枠、供給配分、利用条件|受けられたサービス、待ち日数、利用負担|現場権限が必要。アクセス改善だけで健康改善とはしない|
|生活必需品アクセス|調達、供給、共同購入、受取条件|同等品質での家計負担、入手率、時間|供給者、原価、受取、実際の購入データが必要|

第一候補の優先理由は富への直接性、短い成果サイクル、人口の時間・能力・アクセス制約、実行の証拠、将来の運営者顧客との接続。協力先がない場合の着手対象まで無条件に確定しない。ユーザーへ既存接点を質問済み。

## 対象と介入

初期は一つの運営ネットワーク。外部顧客が実際に必要とする有給案件が存在し、通常運用で未充足/遅延/不適切な配分が観測できること。Manager実験用の架空案件や、創業者が追加支出した予算だけで所得を増やす設計にはしない。

案件と人の時間・能力・要件・原価を表し、候補となる構造変更を有限集合にする。仕事内容と品質条件を守り、運営者が変更できる項目だけをActionにする。案件分割で総作業時間や管理費が増える場合は費用に含める。真に必要な資格要件は除去しない。

## 中核経路

人口/需要根拠 → 時間・能力・アクセスの制約 → 候補ルール → 応答/完了予測 → 予算・品質制約つき選択 → 運営への適用 → 状態readback → 完了・支払観測 → 独立評価 → 更新。

既存Environment Labの契約を使う。初期は統計モデル/明示的行動モデルと単純な割当・探索を比較する。必要性を測定する前に巨大LLM・二層RLを必須にしない。モデル更新用データと最終評価を分離する。

## 主要指標と生活上の意味

主要アウトカム: 事前定義した参加可能集団における、一人当たり実現純所得。入金から記録可能な直接費用・手数料を引き、仕事を得なかった人もゼロとして含める。期間内完了と後日の支払を別に記録する。費用欠損はunknownで、推定純利益を実測として出さない。

時間は別指標として総作業時間/報酬額を報告し、時給を恣意的に仮定して主要所得から差し引かない。運営/Manager/買い手の費用、退款・品質・再作業、完了日数、所得分布、受益者数、最低群、以前の利用者が失った機会も報告する。所得総額だけが同じで受益者が入れ替わった場合は分配の変化として表す。

目標値や改善率を先に実績として書かない。得られた差、信頼区間、母数、比較条件、失敗、変更の費用を公開する。小さいpilotでは効果量と不確実性を報告し、大きな母集団への一般化を保証しない。

## 比較と識別

通常運用とManager選択を同じ外部予算・時間枠・品質条件で比較する。共有案件や人の流出があるため、個人独立のRCTを機械的に適用しない。分離可能なら資源プールを単位にした無作為比較。不可なら事前固定したswitchback/段階導入を検討し、案件構成、日付、学習、carryover、干渉を明示する。単純なbefore/afterだけで因果効果確定とはしない。

設計を固定する前に、baseline分散・案件到来・支払遅延・cluster数を読み、検出できる効果を見積もる。10月末に入金が間に合わない場合、完了や契約を所得として代用しない。

## 今月に示せる証拠

実装された環境変更とreadback、事前予測、比較条件、実際の入金/費用/負担、集団別結果、再現可能な公開コード。public releaseは許諾データまたは取得手順・合成fixtureを含み、個人情報・既存credential・顧客原票を含まない。

協力先・権限・需要が揃わなければ、同じコードでsimulation policy評価と実データprediction評価を行う。ただしそれを現実の最初の祝福と呼ばない。field未実施を明示する。

## YCと名称

Managerを製品名、Architectを候補生成/環境設計を担当する内部の役割名にする案を推奨。Managerは設計・実行・測定・更新までを含む。

YC/Speedrunでは、一つの生活条件改善を測る初期対象と、汎用のpopulation-response-intervention-evaluation契約を示す。Life Managerの既存売上は実行・販売のtrack recordとして別に報告。初期所得機会市場の需要・支払者・pilot evidenceが事業仮説を支える。

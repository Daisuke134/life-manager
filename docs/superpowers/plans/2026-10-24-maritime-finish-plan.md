# Life Manager Cloud: Capafy-first product, paid growth, and Maritime competition plan

> **For agentic workers:** 実装時は superpowers:executing-plans を使い、各taskを一つずつ完了する。チェックボックスで進捗を記録する。状態と現在cursorの正本は統合SSOTだけに記録する。

**Goal:** Life Managerを一つの販売可能なCloud製品として完成させる。各利用者専用のMaritime VMでブラウザー操作agentがCapafyの調査・制作・出品・許可された配布・結果計測を継続し、利用者には実receiptと収益状態を報告する。同時にAnicca自身のCloud subscriptionを成立させ、英語中心のdistributionとMaritime公式利用者証拠を伸ばして、$10k MRRとhackathon上位を同じ成長ループで目指す。目標値と現在の実績は分けて扱う。

**Architecture:** Life Managerは一つの製品で、LocalとCloudは実行モード。`aniccaai.com/lm`が唯一の公開製品ページで、同じoriginの`/maritime`は認証・開始・状態確認の経路であり、別製品やpilot pageではない。Netlify rewrite経由で既存Railway `life-call` control planeへ接続し、各顧客の実行は専用Maritime VMに分離する。`/auth/google`と`/auth/google/callback`も同じoriginでproxyし、PKCE cookieとcallbackを同一hostに保つ。Railwayはcontrol plane/workerであり、公開Webサイトや各顧客のVMを置く場所ではない。Google sign-inがWebの入口。Calendar/Gmail inbox権限、task/goal/budget入力、payout情報はsignupで求めない。Capafyは最初のCloud収益workflow。VM内のLLM agentが顧客ごとのブラウザーsessionを観察して操作し、商品候補調査・制作・出品・許可された配布・実績確認を行う。job、lease、tenant隔離、予算、secret、Stop、receipt、重複防止は決定的コードで保証し、Capafy業務の判断と画面操作を固定scriptや直接API mutationに置き換えない。Capafyの本人確認・規約・出品確認などplatform gateは迂回しない。新しい製品、別のpublic pilot page、fake/demo stateは作らない。

**利用体験:** Googleログインは本人確認と確認済みメールアドレスの取得だけに使用する。Calendar/Gmail inbox権限、タスク・目標・予算の入力、Telegram、銀行情報はsignupで要求しない。Googleログインだけでは個人Gmail inboxへアクセスできない。ログイン後に、データ保持・自律実行・報告、および対象platformで許されたPublisherアカウントの登録/利用を一度だけ明示確認する。その同意後は日々の指示や各listingごとのLife Manager承認を求めず、認証済みtenantの範囲で仕事を選び、制作・許可された出品/配布・結果照合を続ける。Googleの確認済みemailはplatform contactとLife Manager報告先に使う。認証mailの受信が必要な場合は、同意されたtenant専用mailboxだけを検証/サポート目的で読む。個人Gmailの受信箱は読まない。Capafyが本人しか完了できない規約・本人確認・費用などを課す場合は、それを最初のaccount setup gateとして明示し、反復作業ごとの承認にはしない。法的/identity gateは代行・迂回せず、未完了中の作業と収益は未完了として報告する。Webは単一Life Manager Cloudのphone-first workspace。初回リリースは、実行状態・実結果・メールreceiptを表示するworkspaceで成立させる。ChatGPT風の会話UIは必須にせず、後続の任意機能とする。追加する場合は、入力を認証済みtenantのdurable jobへ結び付け、受付・実行・結果の各状態を実データから表示する。実ジョブへつながらないcanned chatやmock activityは出さない。Calendarは実タスクに必要な時だけ後から接続する。確認済みの仕事・結果はアプリのmail providerから確認済みlogin emailへ送る。Payout情報はsignupで要求せず、Capafyが実際の出金時に求める場合だけその時点で案内する。

**売上モデル:** 利用者がCapafyで得るPublisher売上と、Aniccaが得るLife Manager Cloud subscriptionは別の取引として扱う。Capafy gross sales、proceeds、settled payout、受取現金、Cloud subscription MRR、返金・失敗決済・Maritime/model/配布costを別々に証明する。既存Stripe実装は`life_manager_web_travel` metadata、Google Calendar接続必須、US$29/monthのCalendar workflowであり、新しいCloudの課金実装ではない。CloudにはCalendar接続なしでcheckoutできる専用Stripe product/price、webhookで反映するCloud entitlement、customer portal、cancel/failed-payment/retry/state readbackが必要。Cloudの販売価格とtrial条件は未決定なので、旧Calendar価格を流用・宣伝・請求しない。

**Tech Stack:** 既存Node/CommonJS、Railway life-call/worker、Supabase Auth/Manager state、Maritime tenant VM + LLM agent + Chromium/CDP browser session、Capafy customer-owned browser session and official readback, dedicated Stripe Cloud checkout/webhook entitlement, existing Resend/CFO report, existing UTM/funnel observer.

**Spec:** docs/superpowers/specs/2026-09-25-life-manager-unified-ssot.md の「Keiki × Maritime — 初週Top 30と実利用者1,000人」。最新のAs-Is/To-Be/statusは本計画ではなく、その正本の「更新された現在地・完了までの追跡表」を読む。

# Existing host connection for prepared catalog shadow

Design only, 2026-10-23. Intended repository destination: `products/manager/docs/plans/2026-10-23-host-shadow-connection-design.md`. Parent specification: [research specification](https://github.com/Daisuke134/life-manager/blob/63893622d3b2a872fc3ebcd8ceedfeafc7c433ce/products/manager/docs/MANAGER_PRODUCT_SPEC.md) §1.3.2 row 3 (the research document is not a local main-branch dependency). Accepted helper contract was read with `git show 07a8957c7f115b99204aeccbb1a06a1f693daae8:products/manager/manager_core/owned_provider_shadow.py`; synchronization of that source is a separate prerequisite. No tests, model calls, source changes, commits, or network writes were performed for this design.

## Decision and scope

Connect `compare_prepared_catalog_shadow` inside the exact existing `GitHubActionsCycleHost.prepare_candidate`. Reuse the one selected tuple, checkpoint, owner lock, and deterministic publisher. Keep raw comparison output in `_catalog_shadow_result` on that host. Extend the CLI public summary with exactly one field, `catalog_shadow`, whose value is `None` when comparison did not run and otherwise is the existing fixed projection. No new memory engine, framework, owner, ledger, cycle hook, or planner.

The unchanged `run_owned_cycle` calls `prepare_candidate` only after owner lock, session admission, rollback/occurrence/current-page/delivery recovery, STOP, cadence, and release enablement. It obtains a fresh `host._now()` after preparation and revalidates publication independently. The host comparison must remain inside that already established boundary. `run_catalog_shadow` is explicitly unsuitable because it replans.

Alternatives considered: a cycle-level hook would spread report handling across lifecycle exits and invite stale clock use; a separate CLI planner would violate one selection; a separate shadow owner would duplicate authority and recovery. None is needed. Moving budget admission before client creation would change accepted provider semantics and is deferred; the boundary below describes its actual behavior.

## Exact private interface

In `manager_core/owned_platform_host.py`, add a frozen `CatalogShadowSettings` dataclass with `deadline_monotonic: float`, `client_factory: Callable[[], Any] | None = None` (exclude from repr), `cap_usd: Decimal | None = None`, `upper_usd: Decimal | None = None`. It has no secret field and no operational constructor work. Add constants `CATALOG_SHADOW_MAX_SECONDS = 120`, `CATALOG_SHADOW_PUBLISH_RESERVE_SECONDS = 120`, `CATALOG_SHADOW_REQUEST_TIMEOUT_SECONDS = 30`. Existing `MAX_HOST_SECONDS = 600` remains authoritative.

Extend the existing constructor to `GitHubActionsCycleHost(checkpoint, checkout, source_audit_path, *, context=None, assessment=None, scope=None, catalog_shadow: CatalogShadowSettings | None = None)`. Default `None` means OFF. Initialize `_catalog_shadow_result: dict | None = None`; retain settings privately. Add `_compare_prepared_catalog_shadow(self, prepared: tuple | None) -> None`; it imports the accepted comparator lazily. No caller-supplied comparator/callback authority or generic host interface is introduced.

For selected tuples, `prepare_candidate` must retain and return the original `selected` tuple object, not unpack and reconstruct it after comparison. For prebound candidates construct one tuple, pass that object to comparison and return it. For no candidate preserve existing `(None, None, None)` return behavior and pass `None` to comparison. Invalid/incomplete typed bindings retain their existing exceptions. No additional selection, packet mutation, or changes to `context`, `assessment`, or `scope` arise from advice. OFF does not invoke the comparator or a factory, import OpenAI, or create provider tables.

The comparison gets the same `self.checkpoint`, the exact prepared tuple, `now=self._now()`, `run_id=os.environ['GITHUB_RUN_ID']`, `enabled=True`, settings limits/factory, and the bounded absolute deadline below. Store its return privately only after normal helper completion. `CheckpointUnavailable` propagates unchanged. Ordinary `UNKNOWN`, `SKIPPED`, and any valid model `PASS`/`ASK`/`PROPOSE` result do not control the candidate or publisher. Do not catch arbitrary helper programming errors as successful advice.

Wrap only the supplied lazy client factory to track any successfully returned SDK client. In a `finally` around comparison call each such client's `close()` exactly once, including budget refusal, transport uncertainty, checkpoint failure, or interruption. Suppress ordinary close exceptions without exposing their messages or replacing an active checkpoint exception. Do not retry close or provider creation. This establishes cleanup invocation on every exit; it cannot prove success when an SDK close itself fails.

## Configuration and replay

In `scripts/run_owned_digital_cycle.py`, add `_catalog_shadow_settings(env: Mapping[str, str], *, started_monotonic: float) -> CatalogShadowSettings | None`. Only `run_once` calls it, after taking its process-entry monotonic timestamp and before lease acquisition. It only parses/validates and builds an inert closure. Effective opt-in is `GITHUB_EVENT_NAME == 'workflow_dispatch'` and `MANAGER_CATALOG_SHADOW_ENABLED == 'true'`; every other flag value, including malformed flags, is OFF. `run_control` and preflight do not call it.

Use `AMPERSAND_API_KEY`, `MANAGER_AMPERSAND_MAX_TOTAL_USD`, `MANAGER_AMPERSAND_MAX_CALL_USD`. Missing or whitespace-only money is unconfigured (`None`), never zero or an example budget. Parse nonempty strings as `Decimal`; reuse `provider_budget._money`: finite, `0 < value <= 100`, integral microdollars (up to six meaningful decimals), and require `upper <= cap`. Validate key using `valid_api_key` without normalization. A complete valid configuration captures a lazy `make_client(key, timeout=30)` closure. Any missing/invalid send configuration produces enabled settings with factory/cap/upper all `None`; no error text or raw setting is published. No configurable timeout or deadline environment variable is added.

This deliberate normalization lets the accepted helper read a saved ACKed comparison or prior intent before requiring new-send settings. Saved output preserves its original `run_id` and `compared_at`; prior intent remains `UNKNOWN`, never retried. With neither receipt nor intent, enabled but unconfigured returns the accepted `SKIPPED/PROVIDER_NOT_CONFIGURED`. Existing helper schema/reason vocabulary stays unchanged; malformed and missing send settings share this safe outcome. OFF does not read old results.

Static invalid configuration creates zero SDK clients and zero `CheckpointedProvider` instances. This does **not** claim that live-ledger refusal precedes client creation: the accepted helper validates money, invokes factory, constructs `CheckpointedProvider`, and only then admits durable budget. Persisted cap mismatch or exhausted cumulative budget may therefore create one SDK client, create zero model sessions, return `BUDGET_EXCEEDED`, and close that client. Do not duplicate a budget precheck or silently call this a static-invalid case. Reservations remain cumulative and charged until separate settlement; there is no per-run replenishment or cap rotation.

## Time policy and root ruling

The immutable comparison upper bound is `started_monotonic + 120`, captured at `run_once` entry before context checking/acquisition/planning. Host preparation can only shorten it. Immediately before comparison, capture one monotonic value `m` and fresh aware UTC `n`; use:

`min(settings.deadline_monotonic, self._started_at + 600 - 120, m + (scope.expires_at - n).total_seconds() - 120)`.

Omit the scope term only when prepared is `None`. Expired/invalid scope still follows accepted helper validation. A nonfinite internal deadline is inert OFF with `catalog_shadow=None` and factory/provider zero; do not feed NaN to the comparator. Keep the computed deadline on the host for any repeated preparation and only shorten it, never extend it. No refresh on checkpoint save, result replay, planning completion, or a second call; no replan or scope renewal. The 120-second reserve is a conservative code policy, not a guaranteed publisher completion bound. SDK request timeout is 30 seconds; provider's existing absolute deadline and bounded cancellation grace still apply.

If the deadline has elapsed, the helper returns `SKIPPED/DEADLINE_EXPIRED` before looking up saved state. Thus send configuration may be missing during replay, but replay still needs a live supported candidate/scope and time window under the existing helper order. Insufficient window means live send zero, not a new replay bypass. Publication remains subject to its own fresh host/scope checks. Comparison can consume an already committed cadence slot; a later attempt may be `NOT_DUE`.

Root explicitly ruled out adding a job timestamp. Preserve the existing 13-minute workflow job limit and ACK fence; do not claim knowledge of the remaining GitHub job window, a checkpoint TTL, or guaranteed completion before runner cancellation. `PrivateCheckpoint` exposes no lease-expiry timestamp. The absolute comparison limit and host/scope reserve are local safeguards; hard cancellation retains existing unresolved-state behavior.

## Public boundary

Extend `public_summary(report, *, source_sha=None, receipt_sha=None, store=None, catalog_shadow: dict | None = None)`. Its `catalog_shadow` parameter is raw private comparator output; call `public_catalog_shadow_summary` exactly once, never project an already projected result. Always emit `catalog_shadow`, with `None` for no comparison. Successful normal and cycle-`UNKNOWN` return paths pass `host._catalog_shadow_result` only after their existing checkpoint save/release succeeds. Selector failure, outer runtime/checkpoint failure, and control paths pass no raw result and emit null. A later checkpoint failure must not claim even a locally completed comparison.

The 19 nested keys remain: `schema`, `status`, `reason`, `run_id`, `compared_at`, `operation_id`, `context_sha256`, `baseline_digest`, `candidate_digest`, `baseline_decisions`, `model_status`, `model_decision`, `model_comparison`, `proof_level`, `authorized_execution`, `causal_support`, `human_outcome`, `action_writes`, `settled_cost_usd`. Preserve P0/false/false/NOT_MEASURED/0/null invariants. The stable hash-based `operation_id` is permitted; provider session/turn IDs, advice reason/source IDs, raw provider results, prompts, exception text, paths and credentials are excluded. Outer cycle status, exit code, writes, canary, authentication, E16, proof artifact selection and authority do not depend on nested advice.

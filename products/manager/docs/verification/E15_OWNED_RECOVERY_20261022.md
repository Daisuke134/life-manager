# E15 — durable intent and occurrence reconciliation

OwnedEffectJournal extends the existing outbox module without widening the fixture adapter fence. One SQLite transaction reserves the exact canonical packet plus immutable expected Git parent before dispatch. Only its first claimant receives dispatch=true. A crash before send is deliberately quarantined just like a lost response after send. This favors at-most-once dispatch over availability; no universal exactly-once external effect is claimed.

The journal holds no token and sends nothing. The host must still use original authenticated admission and a Git target compare-and-swap against expected_parent. Leases alone cannot fence an old in-flight owner. The existing Git publisher's non-force push rejects target movement; a future persistent owner must preserve this property. The research branch does not replace that owner.

`reconcile_owned` validates an exact commit occurrence, parent, message, changed paths and all seven immutable bodies through the existing receipt validator. A fixture dictionary is not authenticated proof. The production collector must independently GET official public GitHub endpoints as the existing readback script does. Missing data, transient not-found, wrong parent or errors return UNKNOWN; there is no automatic send retry or ABSENT-based retry permission. Only an exact validated occurrence closes the journal fence as PRESENT.

RED: absent journal interface. GREEN: 8 focused recovery tests use persistent SQLite plus a separate real local Git repository. They cover pre-reservation crash, reserved-before-send crash, commit with lost response/restart, eight concurrent claims, changed intent/key binding, wrong occurrence, transient lookup failure, and old-parent CAS rejection. A successful recovery has exactly one external-fixture commit after baseline and replay-zero; unrelated bytes survive. This is sandbox evidence, not a live durable-host or production resilience claim.

Recovery runbook: preserve the private SQLite volume; stop new effects for unresolved keys; fetch the exact immutable target occurrence and parent through the official collector; verify all bindings; mark PRESENT only after success. If no occurrence is established, remain UNKNOWN and escalate to the owning platform operator. Never delete the database, generate a fresh key or rewrite a different expected parent to escape the fence. Rehydrate tested immutable source separately from private mutable state. No ephemeral CI database counts as persistent deployment storage.

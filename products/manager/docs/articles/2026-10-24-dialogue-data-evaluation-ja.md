# 同じ発話が十行あるとき — 会話データを評価に使う前に

無料公開書籍『予測から介入へ』の追加実習章。2026-10-24。AnnoMIの公開資料を取得し、行数・発話・対話・注釈者の対応を調べた独自解説である。モデルの成績や人への介入効果を新しく測った章ではない。

## まず、一行が何を表すかを調べる

会話モデルを改善したいとき、既存の専門家注釈を使える資料は貴重だ。AnnoMIは、Zixiu Wuらが公開した動機づけ面接のデータセットである。133のデモ対話を専門的に書き起こし、会話中の振る舞いに注釈を付けている。[2022原著](https://doi.org/10.1109/ICASSP43922.2022.9746035)

公開リポジトリにはsimple版とfull版がある。今回取得した固定版では、simple版が9,699行、full版が13,551行だった。同じ資料の二つの版なのに、なぜ行数が違うのだろう。

ここで「full版は学習例が増えている」とすぐ判断すると、評価の単位を間違える。まず、`transcript_id`と`utterance_id`を組にして数える。前者は対話、後者はその中の発話を区別するための列である。

```python
import csv
from collections import Counter

with open("AnnoMI-full.csv", encoding="utf-8-sig", newline="") as f:
    counts = Counter(
        (row["transcript_id"], row["utterance_id"])
        for row in csv.DictReader(f)
    )
print(len(counts))
print(Counter(counts.values()))
```

今回の固定版で得られるのは、uniqueな発話9,699、注釈が一つの発話9,271、注釈が十個ある発話428という対応だ。428発話は7対話に含まれている。増えた3,852行は、同じ発話への追加注釈だった。[固定版リポジトリ](https://github.com/uccollab/AnnoMI/tree/42936645ec3857a9c84ab296a36a3c34b779ef49)

人、対話、発話、注釈者は、それぞれ違う単位を持つ。精度や信頼区間を読む前に、この対応を確認したい。

## 元の著者が解いている部分を、そのまま学ぶ

2023年の拡張論文は、7対話を十人の専門家で注釈し、評価者間の一致を調べたと説明する。その他の126対話には一人ずつが注釈した。解析と実験では、複数の注釈を多数決へ集約している。元の著者が13,551行を独立した発話として評価した、と読み違えてはいけない。[拡張原著](https://www.mdpi.com/1999-5903/15/3/110)

私たちは、simple版の二つの高level labelについて、複数注釈の428発話をfull版と照合した。simple版のラベルがfull版の最多票候補から外れるものはなかった。同数票はtherapist側の分類で4発話、client側の分類で10発話あった。

最初の分類研究なら、この既存simple版を使う方法を検討できる。fine-grainedな注釈が必要になった段階で、full版の不一致や同数票をどう扱うかを決めればよい。必要な用途を決める前に、独自の集約方法を増やす必要はない。

## 分類のラベルは、何を意味するか

therapistの発話には、reflection、question、therapist inputなどの分類がある。clientの発話にはchange、neutral、sustain talkの分類がある。これらは、会話の中で何が表現されたかを調べるための専門家注釈だ。

ある発話がchange talkと分類されても、その人が翌日に何をしたかは、このラベルからは分からない。会話のhigh/low qualityも、治療効果が高かった群と低かった群という意味ではない。資料は、MIのよい例・よくない例を示すデモ映像に由来する。

このデータを直接使うなら、まず会話内の分類やannotation fidelityという問いに合わせる。その後の行動、持続、苦しみの低減については、対応する別の観測が必要になる。

## 評価したい一般化に合わせて分割する

拡張論文のbaselineは、発話のラベルで層別した5-fold cross-validationを使う。原著と同じ結果を再現するなら、その方法と条件をたどる。

一方、新しい対話への一般化を調べたい場合は、同じ対話や同じ映像からの発話が学習側と評価側に分かれない設計を考える。同じ発話への注釈を別splitへ置くことも避ける。今回の資料では133対話が119の映像URLに対応しており、対話だけを分けても映像を共有する可能性がある。

それでも、新しい人物への一般化まで確認できたことにはならない。今回はactorの同一性を調べておらず、外部の人物情報にも結び付けていない。利用できる分割軸と、分からない軸を明記することが評価の一部になる。

## 利用条件は、宣言の出典まで残す

取得したrepoにはLICENSE fileがなく、GitHubのlicense metadataもnullだった。一方、2023拡張論文のData Availabilityは、full版をPublic Domain Licenseで公開すると明記している。この宣言も一次資料として記録する。

ファイルがないことだけで利用禁止と判断せず、存在する利用宣言を読む。ただし、Public Domainという記述を勝手に別のCC0契約へ書き換えたり、原動画を含む全素材のあらゆる権利が保証されたと主張したりもしない。今回行ったのは、資料参照と私有のschema・集計監査である。会話本文や映像を本へ転載していない。

モデルを作る前に、すでにあるデータと方法をここまで理解できる。どのラベルを借り、どの単位で分け、どんなbaselineと比較し、どこまでの結論にとどめるか。その判断を公開することも、次に学ぶ人の時間を節約する研究成果になる。

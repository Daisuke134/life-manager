# R007・R008 — 最小の証拠カードと分類

2026-10-20 / Anicca Manager / End suffering.

## なぜ必要か

R007はURLを保存するだけでは落ちる「誰の、何を、いつ、どう測った数字か」を8枚のJSONカードへ固定する。R008は実験・調査・シミュレーション・ベンチマーク・総説・公式ツール文書・企業報告を区別する。大規模DB、知識グラフ、新しい検索エンジンは作らない。

## 実装

- manager_core/evidence.py: オフラインの厳密な構造検査と読み込み。標準ライブラリのみ。
- manager_core/evidence_types.py: 出典種別と研究設計から表示分類を導出。誇張した分類を拒否。
- evidence/*.json: 原著5件、総説1件、Expected Parrot文書1件、Simile企業報告1件。
- tests/test_evidence_registry.py / test_evidence_types.py: 新規27件。既存と合わせ59件合格。

## 何を保証しないか

検査は構造・指定ラベルの整合性のみ。URLの実在、引用の正確性、研究の妥当性、独立性、実世界への適用可能性を自動認証しない。意図的に虚偽の出典メタデータを登録する人を検知する仕組みでもない。原著の読解が先であり、abstract_only/needs_reviewを残せる。登録は生データの利用権・送金・個人データ取得・設備操作の許可にならない。

## Expected Parrotを踏まえた修正

EDSLは質問、調査票、人物設定、状況、モデル、結果を分け、実行・キャッシュ・人間による検証を支える。Managerだけが人間で検証するという比較は撤回する。Simileにも実測と信頼度検証があり、Aaruの中核行動モデルは本人説明では単なるLLMではない。研究地図には各社の原典、読み取った範囲、比較不能な点を保持する。

# AIが稼ぐ → 人間が豊かになる：Managerへの実装と最初の実験

更新: 2026-10-21 JST。**研究とP0ソフトウェア検証の記録**。ライブ販売、支払い、第三者への介入、受益者増加の報告ではない。

## 今回確認した事実

1. **Andon Labs:** Vending-Bench 2は年単位の**仮想事業の終了時現金残高**を測定。仕入先との取引、延滞、顧客返金、在庫切れ、長期整合性が重要。Project Vend / Pionは**現実の事業**への橋渡しを研究するが、店舗とカフェの人件費・家賃を含めた収益性はシミュレーターの数値に一致しない。原資料: https://andonlabs.com/evals/vending-bench-2、https://andonlabs.com/blog/why-we-built-pion
2. **SWE-Lancer:** 過去の実際の仕事の人間への支払額を使った**仮想的な経済価値評価**であり、モデルにその額が実際に支払われたわけではない。https://openai.com/index/swe-lancer/
3. **METR:** AIが生産性を高めるという直感でも、無作為化された実際の仕事の時間では逆効果になった例がある。その後の追試ではサンプル選択の問題を明示。https://metr.org/blog/2026-02-24-uplift-update/
4. **Life Manager既存コード:** `apps/life-manager/eval/economic-autonomy/` は検証済み外部顧客収益・総費用・返金・継続収益・人間の助け・effect_unknown・証拠の重複を区別。`apps/life-manager/eval/agent-contract/` は安全・heldout・費用・実効性・rollbackで昇格条件を判定。**Managerとは別製品であり、ソース・秘密情報・DB・認証・金銭操作を共有しない**。
5. **公開受益効果:** 同じEITCでも2015年の通知簡素化実験と2022年の約100万件の低コスト通知実験では異なる結果。人への通知を自動化したことが、実際の給付取得や資産増の保証ではない。https://www.aeaweb.org/articles?id=10.1257/aer.20121493、https://swlb2.aeaweb.org/articles?id=10.1257/pol.20200603

### 実装で確定させた結果の区別

| 入力種別 | 経済スコアで認めること | 受益者効果 |
|---|---|---|
| 仮想事業の残高 | `PROXY_NOT_SETTLED_REVENUE`、実収益としては `None` | `NOT_MEASURED` |
| SWE-Lancer型の過去報酬価値 | `PROXY_NOT_SETTLED_REVENUE`、実収益としては `None` | `NOT_MEASURED` |
| 外部顧客の領収書ハッシュと完全な費用集計を持つ**入力値** | `UNAUTHENTICATED_RECONCILED_INPUT`、符号つき収支計算は可能 | 独立認証まで `NOT_MEASURED` |
| 費用項目が不明 | `UNKNOWN_COST_COVERAGE`、純利益 `None` | `NOT_MEASURED` |
| 未決済・返金中 | `SETTLEMENT_NOT_COMPLETE`、純利益 `None` | `NOT_MEASURED` |
| 領収書重複、権限違反、通信結果不明 | `DUPLICATE_RECEIPT` / `POLICY_VIOLATION` / `UNKNOWN_EXTERNAL_EFFECT` | `NOT_MEASURED` |
| 比較デザインを伴う**架空RCT数値** | サンプルとして差分やCIを計算 | `OFFLINE_CAUSAL_ESTIMATE_ONLY` / `OFFLINE_UNCERTAIN_NET_EFFECT` / `OFFLINE_NEGATIVE_NET_EFFECT`。全て**P0** |

**重要:** スコアカード入力の「外部提供者の領収書ハッシュ」をソフトウェア的に検査するだけでは、その領収書が本物とは分からない。K010の独立読み戻しや、金銭機関との正式な照合、権限付きの実世界行動は**未接続**で、**何も外部に実行しない**。従って真の外部収益・受益者純便益に対して、このコードからP1〜P5は発行できない。

## 実際の製品への接続：2つのスコアカード

**Scorecard A: Economic Autonomy**
- 外部顧客による一意な決済済み売上、訂正/返金/税/手数料、API/モデルコスト、商品原価、人件費、広告費を通貨と会計期間を統一して測定。
- 平均利益だけでなく最大損失、赤字比率、実行成功率、収益計上待ち時間、human rescue秒数、未知/重複の件数、安全違反数。
- 事業内で実際に支払った金額と、予測売上・未決済注文・仮想残高を別レーンに保存。経済ベンチマークの外部接続と請求の真偽確認は後工程。

**Scorecard B: Beneficiary Incrementality (Blessing)**
- 「誰に」「どの介入」「いつ」「何もしない対照」「費用/害」を事前固定。
- 現実の出費回避、給付受給、賃金所得、店舗運営やエネルギー削減の**独立した結果**を追跡。
- ランダム化実験や適切な比較研究により、**介入による増分**を推定。企業純利益と受益者純便益を合算しない（単なる価値移転の場合もある）。
- わからなければ `ABSTAIN` / `NO_ACTION` / `NOT_MEASURED`。メリットも害も捏造しない。

## 最初に検証する1つの事業実験（提案、実行未着手）

**適用先:** 既存のLife Manager事業とは別に、権限のある運営者が**監査用に匿名化した収益サマリーだけ**出力する。Life Managerの売れている固定商品、個人データ、重要な本番プロセスを変更しない。自律的な販促を検証する場合は新規/非固定の商品のみを事前に選ぶ。

1. **監査だけ:** Life Manager側の既存 LM-EAB 出力と提供者の収益・返金・費用の対応を読み取り、未決済や重複が消えることを先に調べる。Managerは保存された匿名化スキーマだけを取り込み、元の台帳や認証先へアクセスしない。
2. **シャドー実験:** Managerに「候補A：何もしない」「候補B：運営者に許可された説明文変更」「候補C：許可された販促タイミング変更」を同じ条件で予測させる。外部投稿や売上操作を勝手に行わず、事前予測値を凍結する。
3. **真の試験:** 適法な事業者が適用範囲・期間・予算・撤回・顧客保護を委任した後に、無作為な対象・対照を設定。介入で売上が増えたかと、運営者が支払った費用/労働時間が増えたかを**別に**報告。
4. **独立したreadback:** 投稿成功、商品公開、注文、決済、入金、返金、サポート作業のそれぞれについて適切な提供者の結果を確認。二重計上しない。
5. **最後の指標:** 事前登録した処置群 vs 対照群の**増分純利益**、負の効果、信頼区間、分布、顧客苦情、human rescue、計測に失敗した割合。結果ゼロ・赤字も有益な研究結果として保存。
6. **Blessingへの拡張:** 最初の商業収益が実証できても、受益者がより豊かになった証拠はない。次にエネルギー費用削減、行政給付手続支援、職業支援など、対象者が望み、権限と現実の結果を確認できる介入を1つ選ぶ。

### 昇格ゲート

- **Prototype:** P0で仮想シナリオ、外部操作不可。
- **Read-only:** 契約された非個人サマリーと外部検証を確認するが権限は発行しない。
- **Shadow:** 同条件の実測事後結果とエージェントの事前予測を比較。
- **Controlled pilot:** 発行された可撤回権限の範囲内、十分な電力/金銭予算上限、異常時停止、実運営者の監督あり。
- **Field causal:** 原則事前登録された比較群、客観的実測、害・費用・スピルオーバー評価。条件が不十分ならP4に上げない。

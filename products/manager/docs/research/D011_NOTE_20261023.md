# D011 — 公開報奨と入金証拠の境界（一次資料調査）

更新日: 2026-10-23 JST。対象: D011 / manager research branch.

## 問い → 仮説 → 反証（imozuru 方式）

**問い:** 募集、納品、成果物承認と、支払済みという公開表示が揃えば、実際の受取や人間の生活改善を主張できるか。

**検討結果:** できない。公開された承認と取引表示は異なる事実であり、表記上の「settled」は入力された状態であって決済機関の真正性検証ではない。SHA-256 の一致はバイト列を結び付けるが、誰がその資料を作成したか、受取人が着金したか、別の案件と二重計上していないかは証明しない。

**想定反証:** 承認ページが支払ページとして再使用された場合、同じ URL や同一内容を違う識別子で登録した場合、申告額があとから取消・返金された場合、宣言済み受取額を現金収入として算入すると誤認が起こる。公開元が別 URL でも同じ運営主体の自己申告である可能性が残る。

## 一次資料ロケータ（公式、2026-10-23確認）

- Open Collective public GraphQL API: https://developers.opencollective.com/ — アカウント、寄付、経費、元帳取引の公開読取りが可能。個人銀行口座への着金とは別。
- Open Collective ledger transaction pairs: https://documentation.opencollective.com/advanced/ledger/transaction-pairs-groups-and-perspectives — CREDIT/DEBIT の対を扱う。元帳内の照合は元帳外の受取確認に等しくない。
- GitHub REST attestations: https://docs.github.com/en/rest/repos/attestations — アテステーション一覧取得だけでは十分でなく、署名、署名者、日時を検証する必要がある。
- GitHub CLI verification: https://cli.github.com/manual/gh_attestation_verify — 成果物の出自確認と支払の事実確認は異なる証明。

上記は改訂され得る公式ページで、固定 SHA のページ複製は保存していない。原著コードや文書の無断転載なし。

## D011 原子的実装 — 証拠の使い回し防止（2026-10-23）

**問い:** 決済証憑の source_id が異なるだけで、承認証憑とは独立と判断できるか。

**仮説:** できない。同じ source ID・URL・SHA-256 のいずれかを納品・承認・募集と決済で再使用したら、証拠が独立していない可能性を保守的に判定し、declared receipt を所得額として集計しない。

**反証方法（合成テスト）:** (1) 納品・承認・募集の同一 source を settlement に再使用、(2) ID を変え URL だけ共有、(3) ID と URL を変え SHA-256 だけ共有、(4) 全て異なっても income_status は NOT_VERIFIED。いずれも個人の決済情報を扱わない。

**実装:** `manager_core/opportunity_outcomes.py` の `reconcile_opportunity` に `RECEIPT_EVIDENCE_REUSED` を追加し、`tests/test_opportunity_outcomes.py` に上記の回帰テストを追加。既存の `RECEIPT_SOURCE_MISMATCH` を先に判定する。従来の `DECLARED_SETTLEMENT_RECONCILED` は宣言済み金額の一致を意味するだけで、実入金を認証しない。

**重要な限界:** 別々の URL / ソース / ハッシュでも同じ運営主体が作った自己申告かもしれない。Open Collective のクレジット/デビット元帳ペア（上記一次資料）と、GitHub の成果物アテステーションは銀行入金の証明ではない。支払元の真正性、取消・返金、重複請求、受取機関からの独立読み戻しは未実装のため、D011 の**原タスクは todo のまま**。管理者承認や口座アクセスなしに受領確認を捏造しない。

**検証コマンド:** `python -m unittest tests.test_opportunity_outcomes -v`（環境により discover を使用）、`python -m unittest discover -s tests -v`、`python scripts/check_boundaries.py`、`python scripts/make_roadmap.py --check`。合格した CI run の URL は GitHub Actions の当該コミットに紐づけて読む。

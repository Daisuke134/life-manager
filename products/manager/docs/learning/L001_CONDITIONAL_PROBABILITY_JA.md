# L001 — 条件付き確率（行動予測の最初の土台）

**目的:** 人間の行動を予測するための最も単純な数式 `P(Y|X)` を理解する。実際の人間はまだ使わない。

## 1. 予測対象と状況

- `X`: 予測前に観測された状況。ここでは朝・夕方。
- `Y`: 予測対象の結果。ここでは「歩く / 休む」。
- `P(Y|X)`: 状況 X だったもののうち、結果 Y の割合。

以下は**架空の確率分布**で、HeartStepsの実データではない。人数は例示的に100人相当と考えてよい。

| 状況 | 歩いた | 休んだ | 合計 |
| --- | ---: | ---: | ---: |
| 朝 | 0.18 | 0.12 | 0.30 |
| 夕方 | 0.14 | 0.56 | 0.70 |
| 全体 | 0.32 | 0.68 | 1.00 |

`P(歩く|朝)=0.18/0.30=0.60`、`P(歩く|夕方)=0.14/0.70=0.20`、`P(歩く)=0.18+0.14=0.32`。

## 2. 何がわかり、何がわからないか

- わかる：ある状況で行動する**条件付き確率**。
- わからない：「朝に変更したら」歩く確率が40ポイント増える、という**因果効果**。朝に活動する人と夕方に活動する人は、仕事・体調・本人の好み等が異なる可能性がある。
- わからない：通知を出した場合の効果。通知という介入自体がこのデータには存在しない。

これが次のL005（因果グラフ）やL006（潜在結果）に必要な区別。

## 3. 何を実装したか

`examples/01_probability.py` で joint distribution (同時分布) の検査、条件付き確率、全体の確率を計算する。**確率の合計が1でない、負数、bool、NaN、Infinity、空の表、確率0の条件**などを拒否する。

実行例:

```bash
python3 examples/01_probability.py
python3 -m unittest discover -s tests -p 'test_probability_l001.py' -v
```

出力のSYNTHETIC/NOT causalの表示を消して「実測結果」として再利用しないこと。

## 4. Manager本体との接続

- `P(Y|X)` はまず**予測レイヤー**で使う。
- 介入候補の効果を確かめるには対照群などを用いる**因果評価レイヤー**が別途必要。
- 予測が当たっただけでは人への利益・苦しみの低減を主張できない。

実在の組織の例は `docs/landscape/` に記録。組織の存在や機能を調べることも実験の再現とは別に追跡する。

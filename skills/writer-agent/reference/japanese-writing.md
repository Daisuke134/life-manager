# 日本語記事の執筆と推敲

日本語の記事、解説、ニュースレター、公開用の文章を作成・改訂するときに使う。ユーザー指定の主資料はyomiyasu。二つの指針を、意味を保ったまま読みやすくするために使う。

## 必ず読む資料

- `vendor/japanese-tech-writing/SKILL.md`: 段落と論証、定義、因果関係、根拠の範囲、翻訳調の比喩。
- `vendor/yomiyasu/SKILL.md`: 推敲の主資料。主張・比重・断定の強さ・文の役割を保つ。
- 技術記事は `vendor/yomiyasu/references/domains/tech.md`、業務文は `business.md`、随筆は `essay.md`。必要な構文資料は同パッケージの参照先を読む。

取得元は https://github.com/nanaism/yomiyasu と https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d 。固定版と内容のハッシュ値は `japanese-writing-upstreams.json`。保存した資料は上流の指針で、ユーザーの事実・指示・公開範囲を上書きしない。

## 執筆順

1. 読者の問い、主張に対応する一次資料、事実/仮定/予定の区別を決める。初めて出す専門用語を説明し、段落ごとに論理を進める。
2. 根拠をもとに本文を書く。資料を読んだ経験を、製品を動かした経験として書かない。
3. 原稿を保存し、yomiyasuで推敲する。段落の関係、動作主、主張・条件・確度を読み比べる。短くすることだけを目的にしない。
4. 保存した日本語を静的検査する。`python3 vendor/yomiyasu/scripts/yomiyasu_lint.py <article-ja.md>`。警告は見直し候補であり、正確な専門用語や意味を警告消去のために変えない。修正の試行は上流の上限を守る。
5. 推敲前後を比較する。`python3 vendor/yomiyasu/scripts/yomiyasu_diff.py <before.md> <after.md> --stance=説明`。内容拡充と推敲だけの変更を分ける。追加内容は別途出典を確認する。
6. humanizerと既存の品質・出典・画像・公開確認を使う。意味保存を優先し、文体を何度も変える往復をしない。本文・出典・図の元データ・画像・公開状態を実ファイルとして残す。

長文の詳説では、会社と創業者、読者が使う場面、入力データ、処理と出力、学習と評価、公開されていない部分、限界、他の方法との違いを、説明に必要な順で扱う。ページ数だけで完成を判定しない。

## 言語と公開先

二資料は日本語を対象にする。英文では論証や確度を保つ考え方を参考にできるが、日本語リンターの数値を英語の品質指標にはしない。英文には既存の英語編集手順を使う。

マネージャーの人間シミュレーション解説シリーズは、現在のユーザー指示では無料記事、Xと自社ブログを公開先候補にする。これは他の既存有料出版ループの価格や公開先を一括変更する指示ではない。原稿を読む依頼では保存した原稿を渡し、公開済みと報告しない。実際の公開は公開先のアカウントとURLと既存の公開手順を確認してから行い、公開後のURLと本文・画像を読み戻す。

## 公開解説と内部計画の区別

会社・研究の公開解説は、初心者が対象の目的・仕組み・根拠・限界を理解するために書く。求人、履歴書、マネージャーの内部設計は別資料に保存し、解説へ混ぜない。自社紹介は依頼がある記事の末尾に短く置くにとどめる。Aaru・Simileの個別詳説には自社紹介を入れない。

## 日本語と英語の表記

日本語の公開文章では製品名を「マネージャー」と書く。見出し、本文、標語、図中の文字、ボタンも日本語にそろえ、英語の説明語をそのまま混ぜない。英語の記事とページは英語で書く。英語を直訳しただけの表現は、意味と確度を保った自然な日本語に改める。

ファイル名、関数名、コマンド、URL、出典を特定するための正式名称は正確な表記を残す。技術文書ではこれらを識別子として示し、意味や操作の説明は日本語で書く。上流の二資料は編集のたびに再読し、読んだという申告だけで済ませず、実際の文章を推敲して保存する。

2026年10月12日の補足：会社名、研究名、リポジトリ名などの固有名詞は正式表記を使う。日本語文中でもAaru、Simile、OpenAI、Anthropicなどを独自のカタカナ表記に置き換えない。日本語の説明文を自然に書くことと、固有名詞の表記を変えることは別である。


2026年10月18日の本人指定：専門用語は、その分野と言語で定着した標準的な呼称を優先する。日本語を自然に書くために独自の訳語へ置き換えない。日本語は「ニューロフィードバック」、英語は「neurofeedback」。必要なら正式な用語の後に平易な説明を添える。固有名詞・略語・専門用語の表記と、説明文の言語を区別する。
